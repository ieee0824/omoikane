# Acid3 test26 の重複処理削減とローカル再計測 (2026-10-02)

関連: [Issue #1167](https://github.com/ieee0824/omoikane/issues/1167)、#972、#1117、#1141、PR #1148。

この変更だけでは、ローカルの両モード 100/100 の反復条件を満たしていない。5 秒制限・fixture・採点・エラー判定は維持する。成功した予備試行だけで Issue を解決扱いにしない。

## 変更と確認できた効果

- `WeakRef.deref` ごとの Context kept-object 重複保持を、オブジェクト同一性による集合に置き換える。2 オブジェクトを各 4096 回参照する回帰では、変更前 8194 ハンドル、変更後 2 ハンドル。job 終了前の生存と終了後の回収を検証した。
- Node の内部 `__id` getter を共有する。各 Node の enumerable / non-configurable な own accessor、setter 不在、receiver による検索を維持する。非標準プロパティの getter 関数同一性は共通になる。
- 挿入時の祖先探索を既存 native query で行い、祖先ごとの JS ループと wrapper 取得を減らす。`insertBefore` のみ shadow host を辿り、`appendChild`・Range・MutationObserver の従来の ordinary-tree 境界を維持する。`appendChild` が公開 `parentNode` getter を読む挙動は廃し、native tree を参照する。
- Faithful の停止後の空 tick が test26 の計測値を約 0.03 ms で上書きしていたため、最大 step 時間を記録する。タイムアウトした変更前 Faithful の約 0.03 ms は性能値として使えない。

## 計測条件

Intel Core i7-8665U、Linux x86_64、Rust 1.98.1。変更前は `a7416e78` の source-built binary、変更後は専用 worktree / target の source-built binary を使った。root の test O1 / Boa O2 と default features は Cargo fingerprint の profile / rustc / features 一致でも確認した。baseline target は実行のみで再ビルドしていない。

原 fixture の SHA-256 一致を確認し、他の Cargo / Valgrind を停止した時間に B-A-A-B-A-A 順で実行した。最終系列は `taskset -c 2` でコアを固定し、sysfs の `scaling_cur_freq` を 100 ms ごとに記録した。governor と周波数制限は変更していない。周波数はプロセス全体のサンプルであり、test26 だけの平均ではない。

```sh
<binary> runner_scores_100_in_both_drive_modes --exact --nocapture --test-threads=1
# 固定コア系列では上記の先頭に taskset -c 2 を付ける。
```

機械可読データ・binary/source/fixture の hash は [計測 JSON](acid3-test26-2026-10-02.json) に記録した。途中候補のコア未固定系列も破棄せず区別して収録している。

## このチェックポイントの CPU 2 固定系列

| 順序 | 候補 | DirectDrive | Faithful | 全プロセス平均周波数 |
| --- | --- | --- | --- | --- |
| 1 | 変更前 | 26 / timeout | 100 / 4549 ms | 3.14 GHz |
| 2 | 変更後 | 26 / timeout | 26 / timeout | 2.74 GHz |
| 3 | 変更後 | 26 / timeout | 100 / 5005 ms | 2.82 GHz |
| 4 | 変更前 | 26 / timeout | 26 / timeout | 2.67 GHz |
| 5 | 変更後 | 26 / timeout | 26 / timeout | 2.52 GHz |
| 6 | 変更後 | 26 / timeout | 26 / timeout | 2.55 GHz |

全 6 プロセスが少なくとも一方のモードの失敗により exit 101。変更後にも完走はあるが、両モード反復成功と十分な時間余裕は確認できない。Faithful の step wall time は timer/job の後処理も含むため、完走時の 5005 ms を JS deadline の変更と解釈しない。余裕がない結果として保持する。

同一コアでも周波数が変動した。cgroup throttling は観測されず、user CPU 時間と経過時間は近い。周波数変動が結果に影響し得るが、これだけで全変動の原因を確定したとはしない。タイムアウト値は完了時間ではないため、5 秒を分母とする改善率は算出しない。

別の予備 source 試行では両モード 100 点（DirectDrive 4396 ms、Faithful 4173 ms）だったが、反復で再現しなかった。前後の raw log / JSON は `.artifacts/issue1167/` に保持する。
